# gspo-10000 Benchmark Test

## 数据梳理

- 数据文件: `our_benchamek/data/benchmark.jsonl`
- 样本数: 1114
- 字段: `id`, `input`, `metadata`, `output`
- `input`: 题目正文，通常包含 solver-visible world contract / answer requirements
- `output`: 参考答案，包含复杂公式、条件、推导约束，不适合只做数值 exact match
- `metadata`: 包含 `paper_id`, `subject`, `variant`, `source`, `qwen_labels`, `sota_labels`
- `variant`: 全部为 `direct`
- `source`: 全部为 `path_fold_direct`
- `subject`: 337 个学科/主题标签，覆盖化学、物理、生物医学、控制、分布式系统、机器学习等

## 测试对象

- 名称: `gspo-10000`
- 模型路径: `/mnt/oss/zwl/checkpoints/qwen3_4b_instruct_2507_gspo_mixed_10000_v1`
- 采样次数: 32 次/题
- 推理资源: 4 卡 vLLM tensor parallel
- Judge: DeepSeek API `deepseek-v4-flash`
- 统计指标: 对每个 run 分别计算平均准确率，即 `run_i_accuracy = correct_i / 1114`

## 判分规则

### 候选答案提取

| 情况 | 提取方式 |
|------|----------|
| 模型输出含 `<final>...</final>` | 从后往前取第一个非占位符的 `<final>` 内容 |
| 模型输出不含 `<final>` | 取整段回答末尾 1000 个字符 |

占位符集合（跳过不算）：`""` `"..."` `"…"` `"N/A"` `"None"` `"null"` `"NULL"` 等。

### 参考答案

直接使用 `benchmark.jsonl` 中的 `output` 字段原文，不做任何提取或预处理。

### 打分

候选答案先做 whitespace-normalized exact match；exact match 记 `1.0`，其余送 LLM Judge。Judge 返回 `true` 记 `1.0`，返回 `false` 记 `0.0`；非 `true`/`false` 响应或 API 重试耗尽会让本次评测失败，不再静默记为 `0.0`。

**Judge Prompt：**
```
[Problem]          ← input 字段原题
[Reference answer] ← output 字段原文
[Candidate answer] ← 提取的候选答案

Is the student candidate equivalent to the reference answer? Reply with exactly one word: true or false.
```

**Judge System Prompt 核心规则：**
1. 只判最终结论，不看推导路径
2. 等价公式、符号变体、元组顺序不同 → 可接受
3. 缺少必要条件、符号/常数错误、多部分答案不完整 → 错误
4. 题目有 answer contract 时必须执行
5. 只回复单个单词：`true` 或 `false`

**返回解析：** strip `<think>` 块后转小写，必须严格等于 `true` 或 `false`。

**并发与重试：**
- 每道题 32 个回答通过 16 线程并发提交 DeepSeek API
- 失败最多重试 3 次，指数退避（`2 × 2^attempt` 秒）
- 重试耗尽抛错终止，避免把 Judge/API 故障混入模型错误

### 汇总指标

```
accuracy_i = 第 i 次 run 中判对题数 / 1114
mean_accuracy_across_runs = mean(accuracy_1, ..., accuracy_32)
```

## 运行命令

完整流程（生成 + 判分）：

```bash
export DEEPSEEK_API_KEY=你的_key
bash our_benchamek/test/run_gspo_10000_deepseek_api.sh
```

等价的完整参数写法：

```bash
export DEEPSEEK_API_KEY=你的_key
python our_benchamek/test/eval_gspo_10000.py \
  --data our_benchamek/data/benchmark.jsonl \
  --model-path /mnt/oss/zwl/checkpoints/qwen3_4b_instruct_2507_gspo_mixed_10000_v1 \
  --runs 32 \
  --tensor-parallel-size 4 \
  --judge-backend deepseek-api \
  --judge-model deepseek-v4-flash \
  --deepseek-base-url https://api.deepseek.com \
  --judge-max-workers 16 \
  --output our_benchamek/test/gspo-10000.results.jsonl \
  --summary our_benchamek/test/gspo-10000.summary.json
```

已有生成结果、只重新判分：

```bash
export DEEPSEEK_API_KEY=你的_key
python our_benchamek/test/eval_gspo_10000.py \
  --skip-generate \
  --generated our_benchamek/test/gspo-10000.generations.jsonl \
  --runs 32 \
  --judge-backend deepseek-api \
  --judge-model deepseek-v4-flash \
  --deepseek-base-url https://api.deepseek.com \
  --judge-max-workers 16 \
  --output our_benchamek/test/gspo-10000.results.jsonl \
  --summary our_benchamek/test/gspo-10000.summary.json
```

## 输出文件

- `our_benchamek/test/gspo-10000.generations.jsonl`: 每题 32 条模型回答
- `our_benchamek/test/gspo-10000.results.jsonl`: 每题每次采样的分数、候选答案、提取方法、判分方法
- `our_benchamek/test/gspo-10000.summary.json`: 32 次各自准确率及均值，最终以 `mean_accuracy_across_runs` 为准
